# Contributing

## Workflow
1. Выбрать GitHub issue.
2. Проверить зависимости issue.
3. Создать отдельную ветку.
4. Реализовать минимальный scope issue.
5. Добавить/обновить тесты и документацию.
6. Открыть PR.
7. После review и CI — merge.

## Commit style
Рекомендуемый формат:
- `feat: ...`
- `fix: ...`
- `docs: ...`
- `test: ...`
- `refactor: ...`
- `chore: ...`

## Запрещено
- напрямую менять main;
- коммитить .env, ключи, токены, пароли;
- менять бизнес-правила «по ходу» реализации;
- делать скрытые breaking changes API.
