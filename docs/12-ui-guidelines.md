# 12. UI Guidelines

## Brand direction
- основной accent: orange;
- white / light gray surfaces;
- black/dark navigation where уместно;
- логотип OCTAGON использовать без перерисовки при наличии оригинального ассета.

## Дизайн-система мобильного приложения

Оформление задано по макету клуба. Токены собраны в `apps/mobile/lib/design/tokens.dart`,
а тема — в `apps/mobile/lib/app_theme.dart`: экраны не задают цвета сами.

| Токен | Значение | Где используется |
|---|---|---|
| `accent` | `#FF6B00` | кнопки, активная вкладка, карточка ближайшей тренировки |
| `accentSoft` | `#FFF0E5` | подложка аватара, мягкие плашки |
| `background` | `#FFFFFF` | фон экранов |
| `surfaceMuted` | `#F4F4F6` | быстрые действия, поля ввода |
| `textPrimary` | `#111114` | заголовки и основной текст |
| `textSecondary` | `#8A8A8F` | подписи, даты |
| `dark` | `#0E0E10` | шапка тренера, сайдбар админки |
| `danger` / `success` / `warning` | `#E23B3B` / `#2E9E5B` / `#FFA726` | статусы |
| `card` радиус | `18` | карточки |
| `control` радиус | `14` | кнопки и поля |

Правила, вытекающие из макета:

- **главный акцент один** — карточка ближайшей тренировки оранжевая, остальные
  поверхности белые или светло-серые. Если оранжевый появится на нескольких
  блоках сразу, акцент перестанет работать;
- **карточки отделяются фоном и тонкой рамкой**, а не тенью;
- **нижняя навигация** — белая, иконка выбранной вкладки оранжевая;
- **тёмная шапка** используется только в приложении тренера (`dark`): она
  визуально отделяет рабочий интерфейс от клиентского приложения участника;
- **иконки не заменяют подпись**: статус передается цветом и текстом, а не только
  цветом (см. Accessibility).

### Шрифт

`ButtonStyle.textStyle` и `AppBarTheme.titleTextStyle` не наследуют текстовую
тему. Если не задать `fontFamily` явно, кнопки и заголовки шапки рисуются другим
шрифтом, чем остальной экран. Семейство задается в `app_theme.dart` для обоих
мест.

## Принципы
- mobile-first;
- крупные touch targets;
- минимальное число действий для посещаемости;
- финансовые статусы должны быть визуально однозначными;
- административные таблицы должны поддерживать поиск и фильтры;
- не использовать цвет как единственный носитель статуса.

## Проверка дизайна

Скриншоты экранов снимаются golden-тестами:

| Файл | Экраны |
|---|---|
| `apps/mobile/test/golden_screens_test.dart` | участник: главная, расписание, новости, профиль |
| `apps/mobile/test/golden_trainer_test.dart` | тренер: оболочка, ученики, журнал посещаемости |

```bash
cd apps/mobile
flutter test --update-goldens test/golden_screens_test.dart test/golden_trainer_test.dart
```

Эталоны лежат в `apps/mobile/test/goldens`. Тесты выполняются только на Windows:
на Linux нет Segoe UI, Flutter подменяет шрифт тестовым, и сравнение с эталонами
не имеет смысла. В CI шаг пропускается.

Важно: экран, отрендеренный без `Scaffold`, не наследует текстовую тему, и текст
на скриншоте получится прямоугольниками. В тестах экраны оборачиваются в
`Scaffold` — так же, как они живут в приложении. Шрифты грузятся helper-ом
`test/support/golden_fonts.dart`.

## Accessibility
- достаточный contrast;
- scalable text;
- semantic labels;
- keyboard navigation в web admin.
