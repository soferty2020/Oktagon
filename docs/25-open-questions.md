# 25. Open Questions / Deferred Decisions

These items must not block MVP unless explicitly promoted.

- exact production hosting provider;
- App Store / Google Play accounts;
- final club timezone configuration;
- email delivery provider for invites/password reset;
- object storage provider;
- standard monthly price model (MVP permits arbitrary amount);
- rules for unused payments/refunds beyond recording transaction: **запись
  возврата сделана** (ADR-0010: возврат — отдельное движение средств, зачтено =
  поступления − возвраты). Открытым остается **зачет** неиспользованной оплаты в
  следующие периоды и пропорциональный пересчет при заморозке внутри месяца: это
  изменение денежной логики, а не запись факта;
- post-MVP grading eligibility rules;
- push provider/configuration;
- competition workflow;
- CRM integration.

## Финансы участника в мобильном приложении (решено)

По `docs/10-mobile-app.md` главная участника включает «статус оплаты текущего
месяца», но финансы закрыты для участника (BR-010, ADR-0013): `MEMBER` не имеет
финансовых прав, а выдача статуса оплаты — это раскрытие финансовых данных.

Сейчас статус оплаты на главной **не показывается**, остальные блоки (ближайшая
тренировка, посещаемость, объявление) работают. Нужно продуктовое решение:

- показывать ли участнику только сводку «оплачен / есть задолженность» без сумм
  (потребует отдельного эндпоинта и права, например `payments.own.view`);
- или убрать пункт из требований к главной, если родитель узнает об оплате другим
  каналом.

**Решение (B):** показывается только факт, без сумм —
`GET /me/athletes/{id}/payment-status`: «оплачено», «частично», «не внесено»,
«не требуется», «уточните у администратора». Доступ — по связи аккаунта со
спортсменом, суммы не сериализуются в ответе. Реализовано в API и мобильном
приложении.

When resolved, update the relevant specification and add ADR when architectural.

## Настройки — требуется решение перед реализацией K5

Утверждено: финансовые правила задолженности должны быть настраиваемыми суперадмином. Не утверждены конкретные варианты переключателей, поведение при частичной оплате и полной оплате, применение новых правил к прошлым месяцам, влияние заморозок и ретроактивных правок расписания. До решения действует BR-004. См. [26-admin-settings.md](26-admin-settings.md).
