**Эпик H — Mobile: выполнено**

Сделано: **H1 Auth** (вход, сессия, токены в защищенном хранилище, обновление,
выход), **H2 Athlete switcher** (список связанных спортсменов, основной по

переписка с отправкой), **H5 Attendance history** (разбивка по занятиям за три
месяца со сводкой), **H6 Planned absence** (родитель предупреждает об отсутствии
на будущем занятии) и нижняя навигация — своя для участника и для тренера.

Для H5 потребовался новый эндпоинт `GET /attendance/athletes/{athleteId}`: сводка
отдает проценты, но по ней нельзя ответить, был ли ребенок 12 ноября. Доступ
проверяется тем же `assertAthleteAccess` (ADR-0006).

Оформление приведено к макету клуба: дизайн-токены в `design/tokens.dart`,
скриншоты экранов проверяются golden-тестами (Windows). 70 тестов,
`flutter analyze` чистый, web-сборка как проверка компиляции; все проверки в CI
(job `mobile`).

Решения по чату:

- доступ по участию, а не по роли (ADR-0011): сервер отдает только диалоги, где
  пользователь состоит;
- в групповом чате видно автора последнего сообщения и метку «тренер»: в чате
  группы пишут и тренер, и другие родители (BR-012);
- отправка блокирует поле до ответа сервера и перезагружает историю — порядок и
  время сообщений остаются серверными;
- при ошибке сети текст возвращается в поле ввода;
- опроса по таймеру нет: на мобильной сети это дороже, чем обновление в момент,
  когда пользователь открыл список.

Решения по экранам тренера:

- «Сегодня» показывает занятия на сегодня, а не расписание на месяц: тренер
  открывает приложение перед занятием;
- отмененные занятия в список не попадают — проводить их не нужно;
- журнал посещаемости держит правки локально до сохранения: тренер отмечает по
  ходу занятия, а не заполняет форму целиком. Сохраняются только измененные
  записи, чтобы не перезаписать отметки с другого устройства;
- повторное нажатие того же статуса снимает правку (нажал по ошибке);
- предупреждение родителя о планируемом отсутствии видно прямо в журнале
  (BR-008), чтобы тренер понимал причину до отметки;
- ученики собираются из групп тренера и дедуплицируются: один ребенок может
  ходить в две группы;
- раздела «Уведомления» нет: API для него не реализован, пустая вкладка
  выглядела бы сломанной.

Статус оплаты на главной не показывается: финансы закрыты для участника
(BR-010, ADR-0013), вопрос вынесен в `docs/25-open-questions.md`.

Не сделано: эпик H закрыт полностью (H1–H10). Сборка APK требует Android SDK,
iOS — macOS.

- K5 Версионирование и управление утвержденными правилами задолженности + regression tests.
- K6 Просмотр audit log только SUPERADMIN с фильтрами и запретом изменения записей.
- K7 Security/e2e tests и документация раздела.

Источник: [26-admin-settings.md](26-admin-settings.md). Эпик не отмечен выполненным.

Сделано: **K2** — хаб `/settings` со ссылками на существующие разделы и местами под
будущие экраны. CRUD не дублируется: филиалы остаются в `/branches`, сотрудники и
права — в `/users`. Категории фильтруются по правам, финансовые правила и журнал
действий видны только SUPERADMIN.

**K1** — профиль клуба: модель `ClubProfile` (единственная строка), `GET/PATCH
/settings/club`, форма в админке. Доступ закрыт `SuperadminGuard` по роли, а не по
праву: документ требует, чтобы индивидуальный grant не открывал настройки. Каждое
изменение пишется в аудит с before/after. Часовой пояс проверяется как IANA-имя
через `Intl.supportedValuesOf` — смещение вроде `+05:00` отклоняется, потому что в
нем не выразить переход на летнее время.

**K4** — спецификация настраиваемых правил долга: `ADR-0014`. Зафиксированы пять
параметров (отметка «оплачено», отсутствие тренировок, заморозка, незаданная
ожидаемая сумма, допуск недоплаты), инварианты, семантика граничных случаев,
ретроспектива (`effective_from` не раньше текущего месяца) и API-схема с preview.
Дефолт воспроизводит BR-004; поведение не менялось — реализация в K5.

**K3** — справочник поясов: 12 ступеней киокушина (включая полоски), фиксированный
набор в контракте, `GET /belt-grades` только для чтения, поле `Athlete.beltGrade` и
дата присвоения. Пояс меняется в карточке спортсмена с правом `athletes.edit`,
показывается в админке и на главной мобильного приложения. Мутаций справочника нет
(404), набор защищён тестом на порядок и подписи.

**K5** — настраиваемые правила долга: модель DebtRule (версии с effective_from), чистый расчет evaluateDebt, GET/POST /settings/finance/debt-rules, история версий, preview POST /finance/debt-rules/preview и страница /settings/finance. Дефолтная версия воспроизводит BR-004 (регрессия: существующие тесты финансов проходят без изменений). effective_from в прошлое запрещен, изменение аудируется. Доступ — только SUPERADMIN.

**K7** — E2E и безопасность: settings.db-e2e-spec.ts на реальной БД проверяет 401 без токена, 403 для STAFF и MEMBER на настройках, неизменяемость аудита (PATCH/DELETE → 404) и справочника поясов (POST/DELETE → 404), маскировку контактов в журнале, отсутствие секретов в ответе профиля, запрет прошлой даты в правилах и конфликт версии. Шаг pnpm test:e2e:db добавлен в CI; прогон всех db-e2e — 53 теста.

**K6** — журнал действий: `GET /audit` с фильтрами по актору, действию, сущности и
периоду, курсорной пагинацией и страница `/settings/audit`. Доступ закрыт
`SuperadminGuard` по роли: STAFF получает 403 даже с индивидуальными grants
(проверено на живом API). Значения before/after проходят через redaction —
контакты, токены и пароли заменяются маской, а не вырезаются: по записи видно, что
поле менялось. Эндпоинтов изменения и удаления записей нет намеренно.

**Аттестации (вне эпиков)** — Certification: дата, ступень (кю/дан, 1..10), присвоенный пояс. Создание меняет текущий пояс в карточке транзакцией, отмена пересчитывает его по последней оставшейся аттестации. Будущая дата и пояс не из справочника отклоняются, каждая операция в аудите.
