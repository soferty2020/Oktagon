# 17. MVP Acceptance Criteria

MVP считается функционально готовым, если проходит end-to-end сценарий:

1. Суперадмин создает филиал.
2. Создает тренера и группу.
3. Создает квартальное расписание.
4. Создает пользователя и карточку спортсмена.
5. Привязывает спортсмена к группе.
6. Пользователь входит в приложение.
7. Пользователь видит ближайшую тренировку.
8. Тренер отмечает посещаемость.
9. Родитель видит результат.
10. Суперадмин фиксирует оплату за календарный месяц.
11. Система корректно рассчитывает задолженность.
12. Суперадмин создает и завершает заморозку задним числом.
13. Уполномоченный сотрудник переносит занятие.
14. Пользователь видит измененное расписание.
15. Родитель и тренер обмениваются личными сообщениями.
16. Участники группы общаются в общем чате.
17. Уполномоченный пользователь публикует новость; пользователи видят ее и могут комментировать.
18. Суперадмин видит базовый dashboard по филиалам.

Также:
- неавторизованный доступ закрыт;
- permissions работают на backend;
- audit log фиксирует критичные изменения;
- staging deployment воспроизводим из репозитория.
