# 10. Mobile App

Одно Flutter-приложение для всех ролей.

## Состояние

Каркас создан: `apps/mobile`, Flutter 3.47.7, Dart 3.13.5.

Сделано:
- **H1 — вход**: экран входа, токены в защищенном хранилище платформы,
  восстановление сессии при запуске, обновление access-токена по refresh, выход;
- **H2 — переключатель спортсменов**: список связанных спортсменов, основного
  выбирает сервер (`isPrimary`), переключение подгружает данные выбранного;
- **H3 — главная участника**: ближайшая тренировка (первое неотменённое занятие
  впереди), посещаемость за текущий месяц с процентом от отмеченных занятий,
  последнее объявление (закрепленное важнее свежего);
- **H4 — расписание**: занятия по дням на месяц вперёд, отмененные пропускаются;
- **H7 — новости**: список опубликованных объявлений, закрепленные сверху;
- **H9 — профиль**: кто вошел, роль, действующие права, выход;
- **H10 — экраны тренера**: тёмная шапка, «Сегодня», календарь, ученики, журнал
  посещаемости, «Ещё»;
- **H8 — чат**: список диалогов с непрочитанными, переписка с отправкой сообщений;
- **H5 — история посещений**: разбивка по занятиям за три месяца со сводкой;
- **H6 — планируемое отсутствие**: родитель предупреждает, что ребенка не будет.

Разделение по роли происходит на клиенте по `role` из ответа сервера: одно
приложение, но разный состав разделов. Выбрать роль вручную нельзя.

## Навигация

**MEMBER** — нижняя панель из пяти вкладок: Главная, Расписание, Новости, Чат,
Профиль. На вкладке «Чат» показывается число непрочитанных: иначе новое
сообщение обнаруживается только при заходе в раздел.

**STAFF** — тёмная шапка с логотипом и четыре вкладки: Сегодня, Календарь,
Ученики, Ещё. Вкладки «Уведомления» нет: API для неё не реализован.

Экраны держатся в `IndexedStack`, поэтому возврат на вкладку не перезагружает
данные.

## Главная MEMBER

- приветствие и переключатель спортсменов;
- пояс выбранного спортсмена (K3): «Жёлтый пояс, с 10.02.2024»;
- статус оплаты за месяц: «оплачено», «частично», «не внесено», «не требуется» или
  «уточните у администратора»; если клуб задал срок — «оплатить до 10.12.2026»,
  а после срока сообщение помечается просроченным. Сумм нет: BR-010 закрывает
  финансы для участника;
- оранжевая карточка ближайшей тренировки — главный акцент экрана;
- быстрые действия: расписание, посещаемость, новости;
- посещаемость за месяц с процентом от отмеченных занятий;
- последнее объявление.

Суммы не показываются: финансы закрыты для участника (BR-010, ADR-0013). Виден
только факт — «оплачено / частично / не внесено / не требуется / уточните у
администратора»: родителю нужен ответ «я всё сделал или нет», а не размер долга.
Доступ — по связи аккаунта со спортсменом; суммы не сериализуются в ответе.

## Экраны тренера (H10)

**Сегодня** — сводка (занятий, групп, учеников) и занятия на сегодня с кнопкой
«Отметить посещаемость». Отмененные занятия не показываются: проводить их не
нужно.

**Календарь** — занятия всех групп тренера на две недели вперёд, сгруппированные
по дням. Две недели, а не одна: неделя может быть пустой из-за каникул, и тренер
решил бы, что занятий нет вообще.

**Ученики** — дети из групп тренера с поиском. Один ребенок может ходить в две
группы — он показывается один раз, с обеими группами.

**Журнал посещаемости** — три состояния на спортсмена: был, не был,
уважительная причина. Отметки хранятся локально до нажатия «Сохранить»: тренер
ведет занятие и отмечает по ходу, а не заполняет форму целиком. Отправляются
только измененные записи, чтобы не перезаписать отметки, сделанные с другого
устройства. При ошибке сети правки не теряются. Предупреждение родителя о
планируемом отсутствии видно прямо в журнале (BR-008).

**Ещё** — профиль тренера и выход.

## Чат (H8)

Доступ определяется **участием**, а не ролью (ADR-0011): сервер отдает только
диалоги, где пользователь состоит, поэтому фильтровать на клиенте не нужно.

**Список диалогов** — групповой чат группы ребёнка и личные переписки с тренером.
В групповом чате под последним сообщением видно автора: иначе непонятно, отвечает
тренер или другой родитель. Число непрочитанных показывается значком на вкладке.

**Переписка** — пузыри: свои справа с акцентом, чужие слева на сером. В групповом
чате у чужого сообщения видно автора и метку «тренер». Удаленное сообщение
показывается как «Сообщение удалено» — текста у него уже нет (ADR-0012).

Решения:

- отправка блокирует поле до ответа сервера и перезагружает историю: порядок и
  время сообщений остаются серверными, локальная копия не расходится с ними;
- при ошибке сети текст возвращается в поле ввода — набирать заново недопустимо;
- список обновляется при возврате из переписки без индикатора загрузки: чтение
  сдвигает отметку о прочитанном на сервере, и значок должен исчезнуть;
- опроса по таймеру нет: на мобильной сети это дороже, чем обновление в момент,
  когда пользователь сам открыл список.

## История посещений и отсутствия (H5, H6)

**История посещений** открывается с главной кнопкой «Посещаемость». Сводка сверху
отвечает «сколько», список ниже — «когда»: процент не показывает, был ли ребенок
на конкретном занятии, а список без сводки заставляет считать вручную. Период —
три месяца: за меньший история выглядит пустой у тех, кто ходит редко.

Процент считается от отмеченных занятий, а не от всех: «0%» у ребенка, которого
еще не начинали отмечать, был бы неверным выводом.

**Планируемое отсутствие** — на карточке будущего занятия в расписании. Причина
необязательна, но тренеру полезна: она отличает болезнь от поездки. Это намерение
родителя, а не факт: итог тренер подтверждает отметкой (BR-008), и предупреждение
видно в журнале занятия.

Для истории потребовался новый эндпоинт `GET /attendance/athletes/{athleteId}`:
сводка отдает проценты, но по ней нельзя ответить, был ли ребенок 12 ноября.
Доступ проверяется тем же `assertAthleteAccess`, что и у остальных операций с
посещаемостью (ADR-0006).

## Проверки

`flutter analyze` и `flutter test` (70 тестов) в CI (job `mobile`), плюс
`flutter build web` как проверка компиляции. Сборка APK требует Android SDK, для
iOS нужен macOS — в CI их нет.

Скриншоты экранов снимаются golden-тестами (`test/goldens`): это тот же движок,
что на устройстве, но без эмулятора. Эталоны сняты на Windows; на Linux Flutter
подменяет шрифт тестовым, поэтому там шаги пропускаются.
