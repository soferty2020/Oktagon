# OCTAGON Admin — промежуточная передача дизайна агенту

**Статус:** DESIGN PREVIEW / PARTIAL IMPLEMENTATION. Не финальное утверждение дизайна. Разрешена подготовка агентом по текущим макетам; не считать остальные экраны и состояния утвержденными.

## Источник дизайна
Figma: https://www.figma.com/design/c5DTybphpHse74fdjtQoPt

Figma — источник визуальной композиции и слоев. GitHub — источник бизнес-логики, API, permissions и кода. При расхождении поведения приоритет у `docs/03-business-rules.md`, `docs/04-roles-permissions.md`, `docs/11-admin-panel.md` и фактических контрактов. Дизайн не разрешает менять бизнес-логику.

## Состояние макетов
Есть: Dashboard, списки спортсменов/групп/тренеров/филиалов/пользователей, расписание, посещаемость, финансы, новости, чаты, настройки, карточки спортсмена/группы/тренера, формы и диалоги, состояния empty/error/loading/success, мобильные и планшетные варианты.

Не утверждено: окончательный логотип, единая компонентная система и Auto Layout на всех экранах, все responsive states, точные тексты, все сценарии. Часть макетов — иллюстративные данные.

## Правила передачи
1. Агент сначала сверяет существующий UI с макетами, не переписывает работающие модули.
2. Никаких фиктивных KPI, данных спортсменов, оплат и дат в production.
3. Правила доступа контролируются на backend; UI лишь отражает разрешения.
4. Реализовать итерациями, прикладывать before/after screenshots.
5. Не внедрять неподтвержденный восстановленный логотип как официальный.
6. PR на каждый этап; визуальная приёмка пользователем до слияния существенных изменений.

## Порядок
1. Shared shell, navigation, tokens, typography.
2. Dashboard, tables and lists.
3. Detail screens and forms.
4. Scheduling, attendance, finance, settings.
5. Responsive refinements and states.

См. `tokens.md`, `screens.md`, `components.md`, `implementation.md`.
