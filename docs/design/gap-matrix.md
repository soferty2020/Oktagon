# Gap matrix: Figma → текущая админка

Артефакт Issue #24. **Код не менялся.** Документ фиксирует разрыв между макетами
и тем, что есть, и предлагает батчи. Реализация начинается только после
одобрения.

## Метод и ограничения

- Figma-файл (`c5DTybphpHse74fdjtQoPt`) агенту недоступен: нет доступа к
  документу. По правилу `docs/design/implementation.md` п.3 «если агент не может
  открыть Figma — остановиться и запросить экспорт, не выдумывать внешний вид»
  ниже разобраны только экраны, для которых есть скриншоты.
- Есть скриншоты: дашборд админки, два мобильных макета (мобильное — вне scope
  этого issue; здесь только админка).
- Токены сверены с `docs/design/tokens.md` и `apps/admin/src/app/globals.css`.
- Доступность API проверена по `openapi.yaml`, а не по подписям на макете.

## Что макет обещает, а продукта нет

Это не «дизайн-долг», это отсутствующие модули. Добавить их под видом дизайна
нельзя — условия issue запрещают неподдерживаемую функциональность.

| Блок макета | Чего нет в продукте | Что это значит |
|---|---|---|
Заявки на пробную тренировку | сущности, API, прав | отдельная задача: лиды, конверсия, уведомления |
Уведомления | модуля событий | отдельная задача |
Соревнования | сущности и API | post-MVP (docs/25) |
«Отчёты» как раздел меню | отдельного раздела, есть `/finance` с динамикой | можно сделать раздел-агрегатор без новых API |

## Риски прав и безопасности

1. **Поиск в шапке.** Серверного поиска нет. Клиентский — только по уже
   загруженным данным: на больших списках это ложное ощущение полноты.
   Предлагать «найти всё» нельзя, пока нет эндпоинта (изменение API — отдельный
   ADR).
2. **Спарклайны KPI.** История есть только у финансов. Рисовать график
   численности по одному значению — выдумка; вариант: показывать спарклайн
   только там, где данные реальны.
3. **Финансы.** Donut и суммы — только при `payments.view`; скрывать
   серверно, не только на клиенте.
4. **«Права пользователя» на главной** раскрывает матрицу прав любому, кто
   видит дашборд. Убрать — это и UX, и безопасность.
5. **Заявки/уведомления/соревнования** нельзя имитировать: пустые блоки с
   подписью «скоро» хуже, чем их отсутствие.

## Критерии визуальной приёмки

Проверяемые, а не «на глаз». Для каждого батча — до/после и набор проверок.

| Критерий | Как проверить |
|---|---|
Цвета только из токенов | `grep -rn "#[0-9a-fA-F]\{6\}" apps/admin/src --include=*.tsx` → 0 (кроме `globals.css`) |
Единый радиус | ни одного `rounded-[N]` вне шкалы, `--radius-card` один |
Отступы из шкалы 4/8/12/16/24/32 | `grep -E "p-[0-9]+|gap-[0-9]+"` → только допустимые значения |
Типографика | не более 5 размеров, один семейный шрифт |
Фокус | у каждого интерактивного элемента виден `focus-visible` |
Контраст ≥ 4.5:1 | axe или ручная проверка палитры |
Touch target ≥ 44px | высота кнопок и полей |
Статусы текстом | ни одного сырого `ACTIVE`/`SCHEDULED` в HTML |
Состояния | у каждого списка есть empty, loading и error |
Нет фиктивных данных | `grep -rn "TODO\|mock\|fake\|hardcode"` → 0 в рантайме |
Скриншоты | `docs/design/before/` и `docs/design/after/` для каждого экрана батча |

Before-скриншоты текущего состояния: `docs/design/before/` — dashboard, groups,

перевода статусов экран будет выглядеть как макет, но останется недоступным.

При реализации батча эти проверки нужно закрепить в CI, иначе они снова
разойдутся.
