# ADR-0008: Collation базы данных и регистронезависимый поиск

- Статус: принято
- Дата: 2026-10-06
- Контекст: docs/08-database.md, docs/14-infrastructure.md, `openapi.yaml`

## Контекст

Поиск по справочникам (пользователи, спортсмены) должен находить записи
независимо от регистра: администратор набирает «серик» и ожидает увидеть
«Серик». Реализация использует `ILIKE` (Prisma `contains` + `mode: 'insensitive'`).

Поведение `ILIKE` для не-ASCII символов зависит от collation базы данных:

| Collation | `'Тренеров' ILIKE '%тренеров%'` |
| --- | --- |
| `C` (в том числе при `initdb --no-locale`) | не совпадает |
| `Russian_Russia.1251` (локаль Windows по умолчанию) | совпадает |
| ICU (`--locale-provider=icu`) | совпадает |

Это обнаружилось при разработке: локальный кластер создавался с
`--no-locale` (collation `C`), поэтому поиск по кириллице молча не работал,
хотя на другой машине работал бы. Разное поведение на локальной машине и в CI
означало бы, что тесты подтверждают не то, что поедет в staging.

Дополнительный риск: локаль Windows по умолчанию 8-битная
(`Russian_Russia.1251`), что для UTF-8 базы данных нежелательно, даже если
поиск работает.

## Решение

Collation задается явно и одинаково во всех окружениях через ICU:

- локальный кластер:
  `initdb --locale-provider=icu --icu-locale=en-US`;
- `docker-compose.yml`:
  `POSTGRES_INITDB_ARGS=--encoding=UTF8 --locale-provider=icu --icu-locale=en-US`;
- CI (`postgres:16-alpine`): тот же `POSTGRES_INITDB_ARGS`.

ICU выбран вместо локали ОС, потому что он не зависит от 8-битных кодировок и
дает одинаковый результат на Windows и Linux.

## Последствия

- Поиск по кириллице работает одинаково локально, в CI и в staging.
- Кластер, созданный с collation `C`, нужно пересоздать: collation базы
  задается при `CREATE DATABASE` и не меняется на месте. Порядок проверки и
  пересоздания — в `docs/27-local-development.md`, раздел про PostgreSQL.
- Существующие базы, созданные без ICU, сохранят прежнее поведение: при
  пересоздании кластера данные нужно перенести (`pg_dump` / `psql`).
- Сортировка строк (`ORDER BY`) для кириллицы тоже определяется collation.
  ICU `en-US` сортирует кириллицу по кодовым точкам, а не по алфавиту. Для
  справочников это приемлемо, но если понадобится алфавитный порядок, следует
  перейти на `--icu-locale=ru-RU` — отдельным решением, потому что это
  изменит порядок выдачи.
- `ILIKE` ищет подстроку, но не учитывает опечатки и раскладку. Расширение
  `pg_trgm` для нечеткого поиска в MVP не вводится (docs/25-open-questions.md).
