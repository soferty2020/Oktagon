# ADR-0016. Залы вместо филиалов

- Статус: принято
- Дата: 2026-11-04
- Контекст: issue #64–#67

## Контекст

В первой модели структура клуба была двухуровневой: филиал (branch) и залы внутри
филиала. Группа могла заниматься в нескольких филиалах (`GroupBranch` с признаком
основного), занятие наследовало филиал группы.

На практике клуб так не работает. У OCTAGON нет «филиалов» как управленческих
единиц — есть адреса, по которым проходят тренировки. Один зал и есть площадка:
у него свой адрес, телефон и вместимость. Группа тренируется в конкретном зале,
иногда — на выезде в другом зале.

Двухуровневая схема создавала лишние сущности и вопросы, на которые не было
ответа: что значит «группа в двух филиалах», какой филиал у занятия, если группа
переехала. Пользователь подтвердил: филиалы не нужны.

## Решение

1. **Филиал упраздняется.** `Branch` и `GroupBranch` удаляются. Адрес и телефон
   переезжают в `Hall`.
2. **Зал — самостоятельная единица.** Поля: название, адрес, телефон,
   вместимость, активность. Зал не принадлежит ничему, кроме клуба.
3. **Группа живёт в одном зале** (`Group.hallId`, nullable на время переноса).
   Создаётся из зала, переносится в другой зал целиком.
4. **Спортсмен привязан к залу** (`Athlete.hallId`): это его основная площадка.
   При переводе в группу другого зала основная площадка пересчитывается.
5. **Занятие может проходить в другом зале.** `TrainingSession.hallId`
   заполняется из группы, но в форме занятия зал можно выбрать другой — выездная
   тренировка. Филиал занятия удалён вместе с сущностью.
6. **Удаление зала блокируется**, если в нём есть группы или предстоящие занятия:
   ошибка `HALL_IN_USE` с числами в сообщении. Иначе группы остались бы без
   площадки, а расписание — без адреса.
7. **Права остаются историческими**: `branches.view` / `branches.manage`
   управляют залами. Переименование кодов потребовало бы миграции прав и
   отзыва выданных доступов; смысл кода теперь «структура клуба».

## Последствия

- Отчёты финансов группируются по залам (`HallFinanceSummary`) вместо филиалов.
- Админка: раздел «Залы» (`/halls`) — список залов, их группы, редактирование.
  Раздел «Филиалы» удалён.
- Мобильное приложение уже показывало `hallName`; изменений нет.
- Данные переносятся миграцией `20261104000000_halls_instead_of_branches`:
  адрес и телефон из филиала → зал, основной филиал группы → её зал, активная
  группа спортсмена → его зал. Потери данных нет.
- Тренеры по-прежнему работают в нескольких залах: привязки к залу у тренера нет,
  он назначается на группы.
