# ADR-0004: Хеширование паролей — Argon2id

Status: Accepted

## Context

`docs/09-api.md` требует хранить пароль как хеш и допускает Argon2id или bcrypt.
`docs/15-security.md` требует HTTPS в production, короткоживущие access-токены и
rate limiting на auth-эндпоинты.

Пока модуль auth не реализован, `apps/api/prisma/seed.ts` пишет временный хеш
формата `scrypt$<salt>$<hash>` через встроенный `node:crypto`. Это решение
нельзя оставлять: алгоритм не финализирован, а как только появятся реальные
пользователи, смена алгоритма превращается в миграцию данных.

Решение нужно зафиксировать до реализации B2 (email/password auth), потому что
формат хеша определяет seed, модуль auth и любую процедуру сброса пароля.

## Decision

Использовать **Argon2id** с параметрами по умолчанию библиотеки `argon2` и
версионированным форматом хранения:

```
$argon2id$v=19$m=<memory>,t=<iterations>,p=<parallelism>$<salt>$<hash>
```

Это стандартный PHC-формат, который генерирует сама библиотека `argon2`.
Версия и параметры хранятся внутри строки хеша, поэтому:

- параметры можно ужесточать без миграции данных — старые хеши продолжают
  проверяться, новые пишутся с новыми параметрами;
- при необходимости поддерживать второй алгоритм достаточно ветвления по
  префиксу строки (`$argon2` / `$2b$` для bcrypt).

Ориентировочные параметры для MVP (2 vCPU / 4 GB RAM по
`docs/14-infrastructure.md`): memory 19456 KiB (19 MiB), iterations 2,
parallelism 1 — рекомендация OWASP для Argon2id.

Временный scrypt из seed должен быть заменен на Argon2id в рамках issue B2;
до этого момента seed не используется на реальных данных.

## Consequences

Плюсы:

- устойчивость к GPU/ASIC-перебору выше, чем у bcrypt;
- версия и параметры в строке хеша — миграция алгоритма не требует изменения
  схемы БД;
- единый формат для seed, auth и будущего сброса пароля.

Минусы и издержки:

- требуется нативная зависимость `argon2`. Она собирается под целевую платформу,
  поэтому в Docker-образе нужен шаг сборки, а для Windows-разработки —
  prebuild-бинарь. Если сборка окажется проблемой в CI, допустимый откат —
  `bcrypt` (формат `$2b$`), решение и причина фиксируются новым ADR;
- память на один хеш выше, чем у bcrypt, что важно при массовых операциях.
  В MVP количество пользователей небольшое, риск несущественный.

## Alternatives

- **bcrypt.** Проще в установке (широко доступны prebuild-бинари), но ограничен
  72 байтами пароля и слабее против GPU-перебора. Отвергнут как основной
  вариант, оставлен как резервный.
- **scrypt (`node:crypto`).** Есть в стандартной библиотеке и уже используется
  как временный. Отвергнут как целевой: параметры нужно задавать вручную и
  хранить отдельно, версионирование формата не дает библиотека.
- **PBKDF2.** Отвергнут как наименее устойчивый к перебору на GPU.
