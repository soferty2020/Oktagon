# AGENTS.md

Этот репозиторий предназначен для мультиагентской разработки. Любой агент обязан считать документы в `docs/` источником истины.

## Порядок чтения
1. `README.md`
2. `docs/00-project-overview.md`
3. `docs/01-mvp-scope.md`
4. `docs/03-business-rules.md`
5. `docs/04-roles-permissions.md`
6. Профильные документы по текущей задаче
7. `docs/17-acceptance-criteria.md`

## Правила
- Не менять бизнес-логику без отдельного ADR и явного согласования.
- Не расширять MVP самовольно.
- Любая реализация должна иметь тесты и соответствовать acceptance criteria.
- API-контракт, схема БД и permissions должны быть согласованы до параллельной реализации клиента и backend.
- Один issue = один логически завершенный результат.
- Ветка: `feat/<issue>-short-name`, `fix/<issue>-short-name`, `docs/<issue>-short-name`.
- PR должен ссылаться на issue.
- Изменения схемы БД выполняются только миграциями.
- Финансовые данные доступны только пользователям с явным permission.
- Все критичные изменения расписания, оплат, заморозок и прав доступа должны попадать в audit log.

## Definition of Done
- код собирается;
- линтер и тесты проходят;
- миграции воспроизводимы;
- обновлена документация;
- acceptance criteria выполнены;
- нет секретов в git;
- PR прошел review.

## Архитектурные решения
Фиксировать в `docs/decisions/ADR-XXXX-*.md`.
